DATABASE TRANSACTION SAFETY
═════════════════════════════════════════════════════════════════════════════════

✅ Transaction Implementation in ReserveSeats:

using (var transaction = await _context.Database.BeginTransactionAsync())
{
    try
    {
        // Step 1: Create Booking record
        var booking = new Booking { UserId, ShowId, ... };
        _context.Bookings.Add(booking);
        await _context.SaveChangesAsync();

        // Step 2: Create BookedSeat records (one per seat)
        foreach (var seatNumber in request.SeatNumbers)
        {
            var category = DetermineSeatCategory(seatNumber);
            var seatPrice = show.SeatPrices.FirstOrDefault(p => p.Category == category);
            var bookedSeat = new BookedSeat { BookingId, ShowId, SeatNumber, ... };
            _context.BookedSeats.Add(bookedSeat);
            totalAmount += seatPrice.Price;
        }

        // Step 3: Update total amount
        booking.TotalAmount = totalAmount;
        await _context.SaveChangesAsync();

        // Step 4: Commit transaction
        await transaction.CommitAsync();
        
        return Json({ success: true, bookingId: booking.Id });
    }
    catch (Exception ex)
    {
        // Step 5: Rollback on any error
        await transaction.RollbackAsync();
        return Json({ success: false, message: "Booking failed" });
    }
}

✅ Safety Guarantees:
   ├─ Atomicity: All changes commit or all rollback
   ├─ Consistency: TotalAmount always = sum of seat prices
   ├─ Isolation: Other users don't see incomplete booking
   ├─ Durability: Once committed, changes persist
   └─ No partial bookings ever created in database

SECURITY IMPLEMENTATION
═════════════════════════════════════════════════════════════════════════════════

✅ Authentication
   ├─ [Authorize] on protected actions
   └─ Unauthenticated users redirected to login

✅ Authorization
   ├─ Ownership verification (booking.UserId == currentUserId)
   ├─ Returns Forbid() (403) if user doesn't own booking
   └─ Prevents data theft between users

✅ CSRF Protection (Cross-Site Request Forgery)
   ├─ @Html.AntiForgeryToken() in views
   ├─ jQuery reads token: $('input[name="__RequestVerificationToken"]').val()
   ├─ AJAX header: {'RequestVerificationToken': token}
   ├─ [ValidateAntiForgeryToken] on controller action
   └─ Invalid token = 400 Bad Request

✅ Input Validation
   ├─ ShowId > 0
   ├─ SeatNumbers not empty
   ├─ Show exists and IsActive
   ├─ Show not started (StartDateTime > UtcNow)
   └─ All validated server-side (never trust client)

✅ Race Condition Prevention
   ├─ Check availability before transaction
   ├─ UNIQUE INDEX on BookedSeat(ShowId, SeatNumber)
   ├─ Transaction ensures atomicity
   └─ Seats already booked → Error response

✅ Error Handling
   ├─ Try-catch with meaningful messages
   ├─ User-friendly error messages
   ├─ Logging for debugging/audits
   ├─ No sensitive data exposed in responses
   └─ Proper HTTP status codes (400, 403, 404, 500)
