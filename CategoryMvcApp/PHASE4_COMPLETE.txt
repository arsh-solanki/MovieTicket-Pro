KEY ARCHITECTURAL DECISIONS IN PHASE 4
═══════════════════════════════════════════════════════════════════════════════

1. SEPARATION OF CONCERNS
   • Entity models (Models/) represent database structure
   • ViewModels (ViewModels/) represent view data requirements
   • Controllers orchestrate transformation between them
   • Views receive only ViewModels (never raw entities)

2. NESTED VIEWMODELS
   • ShowListItemViewModel nested in MovieDetailViewModel
   • SeatCategoryPriceViewModel nested in ShowDetailViewModel and SeatSelectionViewModel
   • BookedSeatDetailViewModel nested in BookingConfirmationViewModel
   → Enables complex data structures without deep nesting

3. DTOs FOR AJAX
   • ReserveSeatsRequest/Response separate from ViewModels
   • Lightweight, focused on API contract
   • JSON serialization/deserialization handled by [FromBody] binding
   → Clean separation between UI pages and AJAX endpoints

4. DATA ANNOTATIONS STRATEGY
   • [Required] for non-nullable fields
   • [StringLength(n)] for text constraints
   • [DataType(...)] for formatting (Date, DateTime, Currency)
   • [Display(Name = "...")] for user-friendly labels
   • [Url], [Range], [RegularExpression] for format validation
   → Enables both validation and UI generation

5. DERIVED FIELDS
   • PriceRange calculated from SeatPrice.Min/Max
   • ConfirmationNumber formatted from BookingId
   • IsUpcoming calculated from ShowTime vs DateTime.UtcNow
   → ViewModels can include calculated values not in entities

6. NULLABLE REFERENCE TYPES
   • string? for optional text fields
   • int? for BookingId in ReserveSeatsResponse (null on failure)
   • List<T> initialized to empty (never null)
   → Type safety + null safety throughout

AJAX INTEGRATION FLOW (Phase 4 → Phase 5)
═══════════════════════════════════════════════════════════════════════════════

PHASE 4 (This Phase): ViewModels & DTOs designed
PHASE 5 (Next Phase): Implementation of AJAX endpoints

Flow Sequence:

1. USER NAVIGATES TO BOOKING PAGE
   ├─ BookingController.SelectSeats(showId) [HttpGet]
   ├─ Loads Show + related data
   ├─ Maps to SeatSelectionViewModel
   └─ Returns View(viewModel)

2. VIEW RENDERS SEAT GRID
   ├─ Razor view displays @Model.MovieTitle, @Model.TheatreName, etc.
   ├─ jQuery iterates @Model.BookedSeats and marks disabled
   ├─ jQuery renders seat grid from @Model.Rows/@Model.Columns
   └─ CSS styling makes seats clickable

3. USER CLICKS SEATS
   ├─ jQuery click handler adds/removes seat from selection array
   ├─ Display running total price from @Model.Prices
   └─ Enable "Reserve" button when ≥1 seat selected

4. USER CLICKS "RESERVE SEATS"
   ├─ jQuery collects selected seat numbers
   ├─ Creates ReserveSeatsRequest { showId: X, seatNumbers: [...] }
   ├─ $.ajax POST /Booking/ReserveSeats with JSON.stringify()
   └─ Server receives via [FromBody] model binding

5. SERVER PROCESSES BOOKING
   ├─ BookingController.ReserveSeats([FromBody] ReserveSeatsRequest)
   ├─ Validates show exists
   ├─ Checks seats still available (race condition protection)
   ├─ Creates Booking + BookedSeats in transaction
   ├─ Returns Json(new ReserveSeatsResponse { Success = true, BookingId = X })
   └─ On error: Returns Json(response { Success = false, Message = "...", ErrorDetails = "..." })

6. CLIENT HANDLES RESPONSE
   ├─ AJAX success callback receives ReserveSeatsResponse JSON
   ├─ if (response.success) → Redirect to /Booking/Confirmation/{bookingId}
   └─ else → Display error message and allow retry

All DTOs and ViewModels defined in Phase 4 support this flow.
