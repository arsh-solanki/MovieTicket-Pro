MovieTicket Pro is a modern, full-stack movie ticket booking platform built with ASP.NET Core MVC.

### 2.3 Key Design Patterns Used

1. **MVC Pattern**
   - Separation of concerns
   - Model: Business logic & database interaction
   - View: Presentation layer (Razor)
   - Controller: Request/response handling

2. **Repository-like Pattern (via DbContext)**
   - Data access abstraction
   - LINQ queries in controllers
   - EF Core lazy loading & eager loading

3. **ViewModel Pattern**
   - Data transfer objects for views
   - Type-safe view data binding
   - Separation from domain entities

4. **Async/Await Pattern**
   - Non-blocking database operations
   - Better scalability
   - Responsive UI

5. **Transaction Pattern**
   - ACID compliance for bookings
   - Rollback on error
   - Ensures data consistency

6. **Authentication/Authorization Pattern**
   - Identity for user management
   - Role-based access control
   - [Authorize] attributes

7. **AJAX Pattern**
   - Real-time seat status updates
   - Smooth booking experience
   - Reduced page reloads

### 6.1 Seat Availability Algorithm
```csharp
// Check seat availability before booking
var bookedSeats = await context.Shows
    .Where(s => s.Id == showId)
    .SelectMany(s => s.BookedSeats.Where(bs => bs.IsActive))
    .ToListAsync();

var requestedSeats = reserveRequest.SeatNumbers;
var conflictingSeats = bookedSeats
    .Where(bs => requestedSeats.Contains(bs.SeatNumber))
    .ToList();

if (conflictingSeats.Any())
{
    return Json(new { 
        success = false, 
        message = $"Seats {conflictingSeats.First().SeatNumber} already booked"
    });
}
```

### 6.2 Seat Pricing Algorithm
```csharp
// Determine seat category based on row
private string DetermineSeatCategory(string seatNumber)
{
    char rowChar = seatNumber[0];
    
    // A-C = Premium (₹500)
    if (rowChar >= 'A' && rowChar <= 'C') return "Premium";
    // D-G = Gold (₹300)
    else if (rowChar >= 'D' && rowChar <= 'G') return "Gold";
    // H-J = Silver (₹150)
    else return "Silver";
}
```

### 6.3 Transaction Safety Pattern
```csharp
using (var transaction = await _context.Database.BeginTransactionAsync())
{
    try
    {
        // Create booking
        var booking = new Booking { /* ... */ };
        _context.Bookings.Add(booking);
        await _context.SaveChangesAsync();
        
        // Create booked seats
        foreach (var seatNumber in request.SeatNumbers)
        {
            var bookedSeat = new BookedSeat { /* ... */ };
            _context.BookedSeats.Add(bookedSeat);
        }
        
        // Update booking total
        booking.TotalAmount = totalAmount;
        await _context.SaveChangesAsync();
        
        // Commit transaction (only if all saves successful)
        await transaction.CommitAsync();
        
        return Json(new { success = true, bookingId = booking.Id });
    }
    catch (Exception ex)
    {
        // Rollback: automatic if exception thrown
        await transaction.RollbackAsync();
        return Json(new { success = false, message = ex.Message });
    }
}
```

## 7. SECURITY IMPLEMENTATION

### 7.1 Authentication (Who are you?)
✓ ASP.NET Core Identity
  - User registration with email validation
  - Password hashing (PBKDF2 by default)
  - Secure login/logout
  - Password recovery (email-based)
  - Two-factor authentication ready

### 7.2 Authorization (What can you do?)
✓ Role-Based Access Control (RBAC)
  - Admin role: Full access to management pages
  - User role: Can only book & view own bookings
  - [Authorize] attribute on sensitive controllers
  - Policy-based authorization support

### 7.3 CSRF Protection (Cross-Site Request Forgery)
✓ AntiForgeryToken implementation
  - @Html.AntiForgeryToken() in forms
  - [ValidateAntiForgeryToken] on POST/PUT actions
  - Token validated on every AJAX request
  - Prevents unauthorized modifications

### 7.4 SQL Injection Prevention
✓ Entity Framework Core
  - Parameterized queries (automatic)
  - LINQ prevents string concatenation
  - No raw SQL queries with string interpolation
  - Database-side constraint enforcement

### 7.5 Data Validation
✓ Multi-layer validation
  - Client-side: HTML5 form validation
  - Server-side: Data annotations ([Required], [StringLength])
  - Business logic: Range checks, referential integrity
  - Secure defaults: Whitelist approach

### 7.6 User Ownership Verification
✓ Booking access control
  ```csharp
  public async Task<IActionResult> Confirmation(int bookingId)
  {
      var userId = User.FindFirstValue(ClaimTypes.NameIdentifier);
      var booking = await _context.Bookings.FindAsync(bookingId);
      
      // Security: Verify ownership
      if (booking.UserId != userId)
          return Forbid(); // 403 Forbidden
      
      return View(booking);
  }
  ```

### 7.7 Secure Password Requirements
✓ Enforced in Program.cs:
  - Minimum 6 characters
  - At least 1 digit
  - At least 1 non-alphanumeric
  - At least 1 uppercase
  - At least 1 lowercase

### 7.8 Lockout Protection
✓ Brute-force attack prevention:
  - 5 failed attempts → 5-minute lockout
  - Automatic unlock after timeout
  - Admin can unlock manually

## 10. GETTING STARTED

### 10.1 System Requirements
- .NET 8.0+ SDK
- SQL Server 2019+ or LocalDB
- Visual Studio 2022 or Visual Studio Code
- 4GB+ RAM recommended
- Modern web browser (Chrome, Firefox, Safari, Edge)

### 10.2 Quick Start (5 Steps)

1. **Clone/Open Project**
   $ cd e:\dot net\CategoryMvcApp

2. **Build Solution**
   $ dotnet build --configuration Release
   Expected: Build succeeded

3. **Apply Migrations & Seed Data**
   $ dotnet ef database update
   
   Seeding runs automatically and creates:
   - 2 Roles (Admin, User)
   - 5 Users (1 admin + 4 customers)
   - 5 Movies
   - 2 Theatres
   - 4 Cinema Screens
   - Seat prices & shows for 7 days

4. **Start Application**
   $ dotnet run
   
   Application starts on: https://localhost:7001
   (or check console for assigned port)

5. **Test Booking Workflow**
   a) Home page loads with movie carousel
   b) Click "View & Book" on any movie
   c) Select a showtime
   d) SelectSeats page appears with interactive grid
   e) Select 3-5 seats (watch price update)
   f) Click "Reserve Seats"
   g) Confirmation page shows booking details
   h) Click "Print" to see print-friendly version

## 11. KNOWN LIMITATIONS & FUTURE IMPROVEMENTS

### 11.1 Current Limitations
1. **Single Database Instance**
   - No read replicas for scaling
   - Single point of failure
   - Solution: Add Redis caching + DB clustering

2. **No Payment Gateway Integration**
   - Bookings are simulated (no actual payment)
   - Solution: Integrate Stripe, PayPal, RazorPay

3. **Basic Reporting**
   - Admin dashboard shows placeholder analytics
   - Solution: Add detailed reports, charts, revenue tracking

4. **Limited Show Management**
   - Shows created via seeding only
   - Solution: Admin interface for show creation/editing

5. **No Email Notifications**
   - Users don't receive booking confirmations
   - Solution: SendGrid/SMTP integration

6. **Single Language**
   - English only
   - Solution: Implement localization (i18n)
