ROLES & ACCESS CONTROL
═════════════════════════════════════════════════════════════════════════════════

TWO ROLES (Seeded in Phase 2):
  1. "Admin" .... Manage content, view reports, /Admin/* pages
  2. "User" .... Browse, search, book tickets (default for new registrations)

ROLE ASSIGNMENT:
  ✓ [Authorize(Roles = "Admin")] → Only admins can access
  ✓ [Authorize(Roles = "User")] → Only users (or admins) can access
  ✓ [Authorize] → Any authenticated user
  ✓ No [Authorize] → Public access

PROTECTING CONTROLLERS:
  [Area("Admin")]
  [Authorize(Roles = "Admin")]
  public class DashboardController : Controller
  {
      public IActionResult Index() { ... }  // Admin only
  }

AUTO-ASSIGN "USER" ROLE ON REGISTRATION (Optional Override)
═════════════════════════════════════════════════════════════════════════════════

After scaffolding, edit Areas/Identity/Pages/Account/Register.cshtml.cs

In OnPostAsync() method, after user is created, add:

    var roleResult = await _userManager.AddToRoleAsync(user, "User");
    if (!roleResult.Succeeded)
    {
        foreach (var error in roleResult.Errors)
        {
            ModelState.AddModelError(string.Empty, error.Description);
        }
        return Page();
    }

This ensures new users can book tickets automatically (without manual admin role assignment).

SECURITY NOTES
═════════════════════════════════════════════════════════════════════════════════

✓ ANTIFORGERY TOKENS
  • All POST/PUT/DELETE forms must validate antiforgery token
  • Added automatically in scaffolded forms
  • Protects against CSRF attacks

✓ ROLE-BASED AUTHORIZATION
  • Server-side validation only (never trust client-side)
  • Use [Authorize(Roles = "Admin")] on sensitive actions
  • Implement row-level security (users see only their data)

✓ HTTPS IN PRODUCTION
  • Always use HTTPS in production
  • Development mode allows HTTP (for testing)
  • Enable HSTS: app.UseHsts();

✓ PASSWORD HASHING
  • Passwords hashed with ASP.NET Core Identity
  • Never store plain text passwords
  • Validate policy: 6+ chars, digit, special char, upper/lower

✓ SECURE COOKIES
  • HttpOnly flag: prevents JavaScript access
  • Secure flag: HTTPS only in production
  • SameSite=Strict: CSRF protection
