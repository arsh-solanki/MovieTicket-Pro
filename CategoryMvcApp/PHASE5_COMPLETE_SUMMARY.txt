KEY FEATURES IMPLEMENTED
═════════════════════════════════════════════════════════════════════════════════

1️⃣ INTERACTIVE SEAT SELECTION
   ├─ 10×15 seat grid (rows A-J, columns 1-15)
   ├─ Three seat states: Available (green), Selected (dark green), Booked (red)
   ├─ Click to select/deselect seats
   ├─ Real-time category-based pricing
   ├─ jQuery handles all interactions
   └─ No page reload required

2️⃣ REAL-TIME PRICE CALCULATION
   ├─ Seat categories: Premium (A-row), Regular (B-row), Economy (C-row)
   ├─ Load prices from database (SeatPrice table)
   ├─ Calculate total: sum of selected seat prices
   ├─ Update UI instantly on seat selection
   └─ Show price breakdown by category

3️⃣ AJAX INTEGRATION
   ├─ GET /Booking/GetSeatStatus/{id} - Fetch booked seats JSON
   ├─ POST /Booking/ReserveSeats - Submit booking JSON
   ├─ Antiforgery token in headers (CSRF protection)
   ├─ JSON request/response format
   ├─ Error handling with user alerts
   └─ Success: Auto-redirect to confirmation

4️⃣ DATABASE TRANSACTION SAFETY
   ├─ using (var transaction = await _context.Database.BeginTransactionAsync())
   ├─ Atomicity: Create Booking + BookedSeats + TotalAmount (all or nothing)
   ├─ Race condition prevention: Availability check before transaction
   ├─ UNIQUE INDEX BookedSeat(ShowId, SeatNumber) at database level
   ├─ Rollback on error: transaction.RollbackAsync()
   └─ No partial bookings in database

5️⃣ USER AUTHORIZATION & SECURITY
   ├─ [Authorize] ensures logged-in users only
   ├─ UserId captured at booking time (ownership record)
   ├─ Confirmation page verifies booking.UserId == currentUserId
   ├─ Unauthorized access returns 403 Forbid
   ├─ Prevents data theft (user can't see other users' bookings)
   └─ CSRF protection via [ValidateAntiForgeryToken]

6️⃣ SEAMLESS USER FLOW
   ├─ STEP 1: Browse movies (Home/Index)
   ├─ STEP 2: View showtimes (Movies/Details)
   ├─ STEP 3: Select seats (Booking/SelectSeats) - Interactive
   ├─ STEP 4: Submit booking (AJAX POST) - Transaction
   ├─ STEP 5: View confirmation (Booking/Confirmation) - Print-ready
   └─ No redirects or page reloads in seat selection

7️⃣ RESPONSIVE DESIGN
   ├─ Desktop: 4-column movie grid, sticky sidebar on seat selection
   ├─ Tablet: 2-3 column grid, adjusted layouts
   ├─ Mobile: 1-2 column grid, stacked sidebar, larger touch targets
   ├─ CSS media queries for breakpoints
   ├─ Flexible seat grid sizing
   └─ Touch-friendly buttons and interactions

8️⃣ PRINT-FRIENDLY CONFIRMATION
   ├─ Dedicated print styles (@media print)
   ├─ Hides buttons, alerts, navigation
   ├─ Optimizes colors for B&W printing
   ├─ A4 page-sized layout

   └─ User can print or save as PDF

  Controller (Action Methods):
    ├─ HomeController.Index() - Movie grid

    ├─ BookingController.SelectSeats(showId) - Seat page

    ├─ BookingController.ReserveSeats([FromBody]) - AJAX POST
    └─ BookingController.Confirmation(bookingId) - Confirmation

DATA FLOW:
  Database (EF Core)
    ↓
  Controllers (Async Task<IActionResult>)
    ↓
  ViewModels (C# classes with data annotations)
    ↓
  Razor Views (@model binding)
    ↓
  HTML + CSS + jQuery (Client-side)
    ↓
  AJAX (POST to server)
    ↓
  JSON Response (Deserialized to DTO)
    ↓
  Database Transaction (Create records)
    ↓
  Success Response → Redirect to Confirmation

SECURITY LAYERS:
  Layer 1: Authentication
    └─ [Authorize] attribute on protected actions

  Layer 2: Authorization
    └─ Ownership verification (booking.UserId == currentUserId)

  Layer 3: CSRF Prevention
    └─ [ValidateAntiForgeryToken] + antiforgery token in AJAX header

  Layer 4: Input Validation
    └─ Server validates ShowId, SeatNumbers, Show availability

  Layer 5: Database Constraints
    └─ UNIQUE INDEX prevents duplicate BookedSeats
    └─ FOREIGN KEY ensures referential integrity

  Layer 6: Error Handling
    └─ Try-catch with transaction rollback
    └─ User-friendly error messages
    └─ Logging for security audits

CODE QUALITY & BEST PRACTICES
═════════════════════════════════════════════════════════════════════════════════

✅ ASYNC/AWAIT PATTERNS
  ├─ All I/O operations: async Task<...>
  ├─ Database queries: .ToListAsync(), .FirstOrDefaultAsync()
  ├─ Transactions: .BeginTransactionAsync(), .CommitAsync()
  ├─ Non-blocking execution
  └─ Scalable for high concurrency

✅ DEPENDENCY INJECTION
  ├─ ApplicationDbContext injected via constructor
  ├─ ILogger<T> for logging
  ├─ Loose coupling, easy to test/mock
  └─ Framework manages lifecycle

✅ LOGGING
  ├─ _logger.LogInformation() for success events
  ├─ _logger.LogWarning() for suspicious activities
  ├─ _logger.LogError() for exceptions
  ├─ Useful for debugging and audits
  └─ Visible in debug output window

✅ ERROR HANDLING
  ├─ Try-catch blocks with meaningful messages
  ├─ Status codes: 400 (bad request), 403 (forbidden), 404 (not found), 500 (server error)
  ├─ User-friendly error messages
  ├─ Server-side validation
  └─ Graceful degradation

✅ CODE STRUCTURE
  ├─ Single responsibility principle
  ├─ Clear method names (verb + noun)
  ├─ Meaningful variable names
  ├─ Proper spacing and indentation
  ├─ XML documentation comments
  └─ DRY (Don't Repeat Yourself)

✅ DATABASE PATTERNS
  ├─ EF Core with fluent API (Phase 2)
  ├─ Include() for eager loading (avoid N+1 queries)
  ├─ Where() filtering with IsActive
  ├─ Transactions for data consistency
  ├─ UNIQUE INDEX for constraint enforcement
  └─ Audit fields (IsActive, timestamps)
