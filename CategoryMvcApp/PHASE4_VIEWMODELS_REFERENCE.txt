────────────────────────────────────────────────────────────────────────────────
MovieCardViewModel (Lightweight)
────────────────────────────────────────────────────────────────────────────────
Purpose:  Display movies in grid/list format (Home page, search results)
Fields:   Id, Title, PosterUrl, ReleaseDate, Description, IsActive
Features: • Short description (truncate if > 100 chars)
          • URL validation for poster
          • No related entities (lightweight)
Used by:  Home/Index → [Display MovieCardViewModel as grid with images]

Example Entity → ViewModel mapping:
    var vm = movies.Select(m => new MovieCardViewModel
    {
        Id = m.Id,
        Title = m.Title,
        PosterUrl = m.PosterUrl,
        ReleaseDate = m.ReleaseDate,
        Description = m.Description.Length > 100 ? 
            m.Description.Substring(0, 100) + "..." : m.Description,
        IsActive = m.IsActive
    }).ToList();

SeatSelectionViewModel (Complex, Core)
────────────────────────────────────────────────────────────────────────────────
Purpose:  Core ViewModel for seat selection/booking page (main booking UX)
Fields:   ShowId, MovieTitle, PosterUrl, TheatreName, ScreenName, StartDateTime,
          DurationMinutes, List<SeatCategoryPriceViewModel> Prices, 
          List<string> BookedSeats, string LayoutJson, int Rows, int Columns
Features: • Full show + movie information
          • List of already-booked seats (for visualization)
          • Seat layout as JSON (screen.LayoutJson) + parsed Rows/Columns
          • All pricing info for category lookup during selection
          • AJAX integration point: jQuery renders seat grid, sends selected seats
Used by:  Booking/SelectSeats/{showId} → [Interactive seat grid map]

Include path: .Include(s => s.Movie)
              .Include(s => s.Screen).ThenInclude(sc => sc.Theatre)
              .Include(s => s.SeatPrices)
              .Include(s => s.BookedSeats)

AJAX Integration flow:
    1. Page loads SeatSelectionViewModel with seat layout & booked seats
    2. jQuery renders 10x15 grid (from Rows/Columns), marks booked seats disabled
    3. User clicks available seats to select them
    4. "Reserve Seats" button triggers AJAX POST /Booking/ReserveSeats
    5. ReserveSeatsRequest payload: { showId, seatNumbers: ["A1", "A2", ...] }
    6. ReserveSeatsResponse returns { success, bookingId, message, errorDetails }
    7. On success: redirect to /Booking/Confirmation/{bookingId}

4. DTOs FOR AJAX INTEGRATION
═══════════════════════════════════════════════════════════════════════════════

────────────────────────────────────────────────────────────────────────────────
ReserveSeatsRequest (Input DTO)
────────────────────────────────────────────────────────────────────────────────
Purpose:  Receive user's seat selections from AJAX POST request
Fields:   int ShowId, List<string> SeatNumbers
Features: • [FromBody] JSON binding
          • Validation attributes (Required, MinLength)
Sent by:  jQuery AJAX from SeatSelectionViewModel page
Received: BookingController.ReserveSeats([FromBody] ReserveSeatsRequest request)

Example jQuery AJAX call:
    var request = {
        showId: @Model.ShowId,
        seatNumbers: ["A1", "A2", "B5"]
    };

    $.ajax({
        type: "POST",
        url: "/Booking/ReserveSeats",
        contentType: "application/json; charset=utf-8",
        dataType: "json",
        data: JSON.stringify(request),
        success: function(response) {
            if (response.success) {
                window.location.href = "/Booking/Confirmation/" + response.bookingId;
            } else {
                alert("Error: " + response.message);
            }
        },
        error: function(xhr) {
            alert("Request failed: " + xhr.statusText);
        }
    });

────────────────────────────────────────────────────────────────────────────────
ReserveSeatsResponse (Output DTO)
────────────────────────────────────────────────────────────────────────────────
Purpose:  Return booking result as JSON to AJAX caller
Fields:   bool Success, string Message, int? BookingId, string ErrorDetails
Features: • Flexible error reporting (Message for user, ErrorDetails for logs)
          • BookingId null if failed, populated if success
Returned: BookingController.ReserveSeats() → Json(response)

Server action skeleton:
    [HttpPost]
    [Authorize]  // Only logged-in users
    public async Task<IActionResult> ReserveSeats([FromBody] ReserveSeatsRequest request)
    {
        try
        {
            // Validate show
            var show = await _context.Shows.FindAsync(request.ShowId);
            if (show == null)
                return Json(new ReserveSeatsResponse 
                { 
                    Success = false, 
                    Message = "Show not found",
                    ErrorDetails = $"ShowId {request.ShowId} invalid"
                });

            // Check seat availability
            var booked = await _context.BookedSeats
                .Where(bs => bs.ShowId == request.ShowId 
                    && request.SeatNumbers.Contains(bs.SeatNumber))
                .CountAsync();

            if (booked > 0)
                return Json(new ReserveSeatsResponse
                {
                    Success = false,
                    Message = "Some seats already booked",
                    ErrorDetails = "Please select different seats"
                });

            // Create booking (in transaction)
            using var transaction = _context.Database.BeginTransaction();
            
            var userId = User.FindFirst(System.Security.Claims.ClaimTypes.NameIdentifier)?.Value;
            var booking = new Booking
            {
                UserId = userId,
                ShowId = request.ShowId,
                BookingDateTime = DateTime.UtcNow,
                Status = BookingStatus.Confirmed,
                IsActive = true
            };

            _context.Bookings.Add(booking);
            await _context.SaveChangesAsync();

            // Add booked seats
            decimal totalAmount = 0;
            var seatPrices = await _context.SeatPrices.Where(p => p.ShowId == request.ShowId).ToListAsync();

            foreach (var seatNum in request.SeatNumbers)
            {
                var category = DetermineSeatCategory(seatNum);  // Your logic
                var price = seatPrices.FirstOrDefault(p => p.Category == category)?.Price ?? 0;
                totalAmount += price;

                _context.BookedSeats.Add(new BookedSeat
                {
                    BookingId = booking.Id,
                    ShowId = request.ShowId,
                    SeatNumber = seatNum,
                    Category = category,
                    Price = price,
                    IsActive = true
                });
            }

            booking.TotalAmount = totalAmount;
            await _context.SaveChangesAsync();
            await transaction.CommitAsync();

            return Json(new ReserveSeatsResponse
            {
                Success = true,
                Message = "Booking confirmed successfully",
                BookingId = booking.Id
            });
        }
        catch (Exception ex)
        {
            return Json(new ReserveSeatsResponse
            {
                Success = false,
                Message = "Booking failed",
                ErrorDetails = ex.Message
            });
        }
    }

6. NEXT PHASE: PHASE 5 – BOOKING CONTROLLER & BUSINESS LOGIC
═══════════════════════════════════════════════════════════════════════════════

After Phase 4 (ViewModels), Phase 5 will create the BookingController with:

Controllers/BookingController.cs
├── [HttpGet]
│   ├── ShowDetails(int id)                 → Show pricing before seat selection
│   └── SelectSeats(int showId)             → Render seat grid + booked seats
├── [HttpPost]
│   └── ReserveSeats([FromBody])            → AJAX endpoint for seat reservation
└── [HttpGet]
    └── Confirmation(int bookingId)         → Display booking confirmation

Key implementation notes for Phase 5:
• All booking operations use [Authorize] attribute (logged-in users only)
• ReserveSeats uses database transaction for atomicity (prevent race conditions)
• Unique index on BookedSeat(ShowId, SeatNumber) prevents double-booking at DB level
• Calculate TotalAmount from SeatPrice entities based on selected seat categories
• Use soft delete pattern: IsActive = true/false (don't physically delete)
• DateTime fields use DateTime.UtcNow (server UTC time)

7. VALIDATION & DATA ANNOTATIONS REFERENCE
═══════════════════════════════════════════════════════════════════════════════

Applied throughout ViewModels:
• [Required]                 – Non-nullable strings, objects, collections
• [StringLength(n)]          – Max length validation
• [Range(min, max)]          – Numeric ranges
• [Url]                      – URL format validation
• [DataType(DataType.Date)]  – DateTime fields
• [DataType(DataType.DateTime)] – DateTime with time
• [DataType(DataType.Currency)] – Decimal price fields
• [Display(Name = "...")]    – User-friendly labels for forms
• [RegularExpression(...)]   – Custom pattern (e.g., seat numbers)
• [MinLength(n)]             – Minimum items in collection

All annotations follow ASP.NET Core standards and integrate with:
• Model Binding (automatic JSON/form deserialization)
• View Rendering ([Display] labels in generated HTML)
• Validation (client-side via unobtrusive validation JS)
• Documentation (IntelliSense in strongly-typed views)
