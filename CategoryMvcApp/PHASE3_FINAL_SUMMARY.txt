STEP 5: (Optional) Override Register.cshtml.cs
───────────────────────────────────────────────

If you want new users to automatically get the "User" role:

Edit: Areas/Identity/Pages/Account/Register.cshtml.cs

Find the OnPostAsync() method. Locate this code:

    var result = await _userManager.CreateAsync(user, Input.Password);
    if (result.Succeeded)
    {
        // ... existing code ...
    }

After "if (result.Succeeded)", add this code:

    // Auto-assign "User" role
    var roleResult = await _userManager.AddToRoleAsync(user, "User");
    if (!roleResult.Succeeded)
    {
        foreach (var error in roleResult.Errors)
        {
            ModelState.AddModelError(string.Empty, error.Description);
        }
        return Page();
    }

See PHASE3_REGISTER_OVERRIDE_REFERENCE.cs for complete example.

═════════════════════════════════════════════════════════════════════════════════
  AUTHENTICATION FLOW (How It Works)
═════════════════════════════════════════════════════════════════════════════════

USER REQUEST:

    User clicks "Login" → /Identity/Account/Login page loads

USER ENTERS CREDENTIALS:

    Email: admin@movie.com
    Password: Admin@123!

SERVER VALIDATES:

    1. Middleware receives request
    2. Identity validates password against hash in database
    3. Password matches → Authentication succeeds
    4. Creates authentication cookie

MIDDLEWARE CREATES COOKIE:

    • Cookie name: .AspNetCore.Identity.Application
    • HttpOnly flag: Prevents JavaScript access
    • Secure flag: HTTPS only in production
    • SameSite: Prevents CSRF attacks

SUBSEQUENT REQUESTS:

    Cookie is sent with every request
    Middleware reads cookie:
    • User.Identity.IsAuthenticated = true
    • User.Identity.Name = "admin@movie.com"
    • User.Claims contains roles: Admin

AUTHORIZATION CHECK:

    Request to /Admin/Dashboard:
    • [Authorize(Roles = "Admin")] checks
    • Is user.Identity.IsAuthenticated? YES
    • Is user in "Admin" role? YES
    • Execute action: DashboardController.Index()
    • Return view

═════════════════════════════════════════════════════════════════════════════════
  PROTECTING ACTIONS WITH [Authorize]
═════════════════════════════════════════════════════════════════════════════════

REQUIRE ADMIN ROLE (Entire Controller):

    [Area("Admin")]
    [Authorize(Roles = "Admin")]
    public class MoviesController : Controller
    {
        public IActionResult Index() { ... }
        public IActionResult Create() { ... }
        public IActionResult Edit(int id) { ... }
        public IActionResult Delete(int id) { ... }
    }

REQUIRE USER ROLE (Specific Action):

    [Authorize(Roles = "User")]
    public IActionResult MyBookings() { ... }

REQUIRE ANY AUTHENTICATION:

    [Authorize]
    public IActionResult Profile() { ... }

ROW-LEVEL SECURITY (Users see only their data):

    [Authorize]
    public async Task<IActionResult> MyBookings()
    {
        var userId = User.FindFirst(ClaimTypes.NameIdentifier)?.Value;
        var bookings = await _db.Bookings
            .Where(b => b.UserId == userId && b.IsActive)
            .ToListAsync();
        return View(bookings);
    }

CHECK ROLE IN VIEW:

    @if (User.IsInRole("Admin"))
    {
        <a href="/Admin/Dashboard">Admin Panel</a>
    }

═════════════════════════════════════════════════════════════════════════════════
  SECURITY BEST PRACTICES
═════════════════════════════════════════════════════════════════════════════════

✓ ANTIFORGERY TOKENS
  • All POST/PUT/DELETE actions must validate token
  • Prevents CSRF (Cross-Site Request Forgery)
  • Razor forms include automatically: @Html.AntiForgeryToken()

✓ NEVER TRUST CLIENT-SIDE AUTHORIZATION
  • Always verify role server-side
  • JavaScript can be manipulated

✓ ROW-LEVEL SECURITY
  • Users should only see their own data
  • Filter queries by User.FindFirst(ClaimTypes.NameIdentifier)?.Value

✓ HTTPS IN PRODUCTION
  • Always use HTTPS for authentication
  • app.UseHsts(); enforces HTTPS redirects

✓ PASSWORD HASHING
  • Never store plain text passwords
  • ASP.NET Core Identity handles hashing
  • Password policy enforced: 6+ chars, digit, special, upper, lower

✓ SECURE COOKIES
  • HttpOnly: JavaScript cannot access
  • Secure: HTTPS only (production)
  • SameSite: CSRF protection
